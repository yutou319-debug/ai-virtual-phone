# 每天随机联系（个人 Supabase）

这是独立的每日云端规则：即使几天没有打开 Float、没有回复，仍每天重新排期。不是原来的“沉默超过 X 分钟，最多连发 3 次”。

默认每个角色每天最多一次生成请求，北京时间 08:00–23:00 内随机选择一分钟，避开你设置的安静时段。一次回复可以分成多个聊天气泡/通知，仍只进行一次模型请求。它会正常消耗文字模型额度；不自动生成图片或启动快捷动作。失败或结果不确定时不自动重试，第二天继续排期。它不会限制你正常聊天时的模型调用。

## 额度恢复后的操作

1. Netlify 发布 GitHub `main` 最新代码，等部署状态变成 Published。
2. 从主屏幕打开 Float，确认已加载新版；必要时关闭后重新打开。
3. 在“云服务部署”重新部署个人 Supabase 的离线推送。仅发布 Netlify 不会更新 Supabase 的表、定时任务和云函数。此次需要个人云 schema 4。
4. 保持“云端任务”和“离线推送”开启，点击测试确认本设备能收到通知。
5. 在“离线推送 → 定时主动消息”里选择“每天随机联系（云端持续）”，选择路辰，点击创建。只有云端确认成功后才保存规则。
6. 若只想每天随机联系一次，删除旧的“沉默超过 1 小时”规则。两种规则各自独立，保留两种就会分别触发。

创建当天会在剩余可用时段排期；如果当天没有剩余时段，从第二天开始。不补发错过几天的消息。任务扫描约每分钟一次，再加模型生成与推送的耗时，不保证选定时刻立刻收到通知。

删除规则必须联网，收到云端确认才从列表移除；删除未确认时请重试。已经开始的模型请求可能已产生费用，关闭无法撤回这次请求。更改安静时段后应确认没有出现云端更新失败提示。若安静时段覆盖全部每日窗口，云端暂不生成，恢复可用时段后继续排期。

不需要“后台保活”，也不需要每天打开 Float。Supabase 的 cron、项目、模型 API 和系统推送订阅需仍然可用；iOS 的专注模式等设置可能影响通知显示。云端使用最后同步的角色配置和聊天上下文，并补充最近五次每日联系，避免每天重复同一话题。修改 API Key 或角色设定后打开 Float 同步一次。

## 去重与取消

- 规则标识按角色固定；数据库按 owner + 角色 + 北京日期唯一保存任务。
- 每天的排期只插入一次，不覆盖已经认领、成功、失败或当日取消的任务。
- 云函数原子认领 `pending → running`，且仅允许认领到期任务。
- 当天任务超时记为失败，cron 不把它重新排队。
- 删除先将规则设为关闭，再撤销任务；普通快照刷新只更新启用的规则，不能复活已关闭规则。
- 每日任务调用模型前和投递结果前再次检查规则、日期与安静时段。只执行一个文字模型请求，不武装工具续跑。

## 本地验证

`node scripts/check-daily-contact.cjs` 检查跨时区安静时段、实际云生成器的并发认领、失败不重试、关闭/过期任务不调用模型；全部使用模拟 API，不产生费用。

要执行真实 PostgreSQL 排期 SQL 测试，可在临时目录安装 `@electric-sql/pglite`，再把安装位置传入 `PGLITE_MODULE`：

```sh
npm install --prefix /tmp/float-daily-db @electric-sql/pglite --no-audit --no-fund
PGLITE_MODULE=/tmp/float-daily-db/node_modules/@electric-sql/pglite node scripts/check-daily-contact.cjs
```

该测试验证重复扫描不改变已排期时刻、第二天自动排期、失败不重新生成、关闭/完整安静窗口不排期，并验证数据库本身不在 UTC 时仍按北京时间工作。真实 iPhone 推送需发布后验证。
