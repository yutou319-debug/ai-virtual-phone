# 图片上下文和用户确认标注

本改动不包含部署，不建立人脸模板，不进行跨照片的现实人物身份识别。

## 使用

- 发送图片仍然自动随聊天交给已开启图片识别的模型，不要求每次确认。
- 聊天设置 → 传入最近图片数：新会话默认 3，明确保存的旧值（包括 0 和 1）保留。用户照片优先于表情和助手图片；建议先用 2–3 张。
- 聊天设置 → 图片细节增强：默认关闭（512 像素、低细节）。开启后最长边 1024，兼容接口使用 auto 细节。可能增加输入费用。
- 长按用户图片 → 图片标注：可记录和纠正“这张图右边是我”等用户确认的信息；最新保存覆盖旧值。
- 聊天设置 → 本地图片标注 → 管理图片标注：查看和删除本会话记录，即使原消息已删除也可清理。
- 标注仅匹配同一会话、同一消息、同一图片引用的 SHA-256 摘要。图片标注不会自动推广到其他照片。

## 舒芙蕾 / Gemini

若站方为该模型提供 OpenAI 兼容接口，Float 应使用 Custom 服务商、Base URL `https://shufulei.net/v1`、站方提供的完整模型名，并打开图片识别。构建出的地址为 `/v1/chat/completions`，图片以 `image_url` multipart 保留。

Google 服务商选项表示原生 Gemini 协议，不等同于“模型名称是 Gemini”。原生接口的普通远程图片会先在浏览器下载、转成内嵌图片；受 CORS、失效链接等影响下载失败时直接报错，避免无图继续请求。其他调用路径未准备好内嵌图片时，适配器也会阻止静默替换为文字占位符。

本站公开模型列表不是逐个模型的视觉验收证明。本轮没有使用真实 Key 发起模型请求；上线前需用一条非敏感的普通多图消息核实选定模型的实际行为。

## 隐私、费用与边界

独立的本地 IndexedDB `FloatVisualAnnotations` 保存用户标注、消息/会话 ID、更新时间和图片引用的摘要，不重复保存照片、脸部特征或 API Key；不纳入现有自动云备份。使用匹配图片时，标注文本会随同原有聊天请求发给配置的模型服务商，云端生成任务也会包含这些请求文本。服务商的数据保留、训练政策需另行确认。

标注保存、纠正、查询、删除均不调用模型。不新增视觉摘要、向量嵌入或自动重试；多图/高细节可能增加原有一次请求的输入费用和延迟，按次收费模型需核对站方规则。内嵌图片合计超过 600,000 字符时，在请求前提示减量，为云端任务封装留空间；这不是完整请求永不超限的保证。

纠正记录独立于普通历史文本保存，但只有原图片仍在本轮有效上下文内时才附加；原图片被历史截断或图片数量限制排除后，不声称仍能看到原图。不自动将被截断的照片重新上传。

## 验证

- `node scripts/check-visual-context.cjs`：多图预算、表情优先级、原消息不变、纠正覆盖、删除、会话/图片隔离、模拟历史截断、换站位/衣服/发型不继承标签、兼容/原生多图请求、视觉关闭、缺失图片，以及标注组件保存/删除与设置管理入口。
- `npx tsc --noEmit --pretty false`
- `node scripts/check-call-session.cjs`
- `node scripts/check-single-reply-executor.cjs`

这些检查使用模拟图像引用和存储，不上传真实照片，不产生付费 API 调用。未做真机 Safari 视觉验收或生产部署。
