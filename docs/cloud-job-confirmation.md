## 单次回复

`push_jobs` 主键为 `id`，另有唯一索引 `(user_id, trigger_key)`。PostgREST 的 `resolution=ignore-duplicates` 默认只处理主键冲突；每次新 UUID 对应相同触发键时，原实现仍报 23505。现在显式设置 `on_conflict=user_id,trigger_key`，随后读取同一任务。已完成、运行中、失败的任务均不替换，不追加模型调用。

回归测试先模拟 PostgREST 的默认主键行为复现失败，再验证 20 个并发提交共享同一个任务和一次付费执行。此前的 mock 错把所有触发键冲突当作已正确忽略，已修正。

## 定时联系

本地 `executeTimedWakeTool` 原先保存本机排期后直接返回成功，异步提交云端且吞掉错误。现在等待一次云端确认，明确区分“云端已确认”和“仅本机定时”。注册失败或应答丢失不自动重试，保留本机定时并说明离线送达不能保证。确认预约仅代表成功入队，不代表模型生成和通知投递必然成功。

后续补齐：普通聊天在 `generateChatCompletionCore` 的单次云端执行入口提前交接，未经过本地工具循环。现在启用定时能力时，从最后一条用户输入解析明确的定时请求（如“40分再给我发一个”“五分钟后找我”“明天上午八点提醒我”，时区北京时间），随原有请求提交，无额外识别模型调用。云端先创建一次 `cloud-timedwake:<原回复任务ID>` 并读取确认，再把实际执行结果加入当前模型请求。关闭能力、时间不明、历史叙述、否定请求、超出七天或安静时段不创建。失败或应答丢失不重复 POST；读回未确认时明确要求模型不得承诺成功。不支持的复杂时间表达需到离线推送页明确创建。

未来任务沿用现有模型快照和原子认领机制，并剥除定时注册字段、快捷工具和原消息排序锚点；仅执行一次简短主动联系，不递归排期。绑定了微信云助手时复用现有微信送达和 Float 同步路径。预约产生一次用户明确请求的未来模型生成，注册本身不调用模型。

网关快照上限由原先 900,000 字符改为 4 MiB 实际 UTF-8 字节数；中文和图片都按真实传输大小计数。不会自动截断历史、自动重试、提高模型输出上限或多生成一份回复。修复需同步发布网页和个人 Supabase 的 ai-phone-push、push-generate。微信核心升级协议 5，拒绝加载缺少语音转写和表情包过滤的旧桶代码，回退本次内置核心。
