# 微信表情包素材校验（待发布）

症状：模型输出不存在的 `[表情包:名称]` 后，微信发送默认紫色模板图，Float 则显示名称占位。
原因：云助手素材匹配失败后落入通用媒体模板回退，没有校验可发送表情的清单。

修复：云助手在保存回复和提取快捷动作前移除没有真实素材的表情标记，保留其余正文。
单独只有无效表情时改成一句无法发送的文字说明，完成原有回复确认，避免下一轮重新生成扣费。
媒体组装也拒绝未知表情，不再生成默认表情占位图片。匹配按完整名称（允许首尾空白）进行，不猜测近似名称。
浏览器微信接入同样只发送角色已配置的素材；外链素材读取失败不伪造模板图。

验证：`node scripts/check-weixin-stickers.cjs`、微信批次/语音/提示词回归及 TypeScript 检查。
不增加模型调用，不为不存在的表情调用生图接口，不修改历史消息。
这不能让模型永不编造名称，但能阻止编造名称被作为真实表情发送。

仅保存 GitHub 待发布分支，不合并 main，不部署 Netlify 或 Supabase。
